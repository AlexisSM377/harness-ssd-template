  plan's own verification command for "no nested skill folders"

## Findings considered and rejected

- Replicating the screenshot's nested `skills/<category>/<skill>/` folder
  structure literally: rejected. Confirmed against
  anthropics/claude-code#28266 and #40640 that Claude Code only scans
  `.claude/skills/` one level deep — two-level nesting silently fails to
  auto-load. This is the actual root cause of the auto-detect problem the
  user reported, not something the reorg should reproduce.
- Adding `hooks/`, `MEMORY.md`, `run.sh`, `install.sh`, `.mcp.json` (the rest
  of the screenshot's "loopkit" vault layout): rejected — user confirmed
  scope is skills/ only. That vault is a different harness style (autonomous
  loop runner) than this repo's spec-gated, human-approval model; importing
  its scaffolding wholesale isn't a fit.

## Direction findings surfaced (not planned this round)

From the same 2026-07-28 self-audit that produced 007-010. Not rejected —
just not selected for planning yet; presented separately from the fix
findings above since these are forward-looking options, not bugs.

- **Promote the `plans/` self-improvement loop as a documented downstream
  convention.** This repo has dogfooded it successfully (6 plans authored,
  reviewed, merged via `/improve`), but nothing under `template/` tells a
  downstream project this pattern exists for auditing their own app code.
  Cheap (a doc paragraph), but it's a pointer to an external tool
  (`/improve`), not core harness content.
- **Ship a second concrete multi-IA entry-point example** (e.g. a 3-line
  `GEMINI.md` stub alongside `CLAUDE.md`). README's "componente 4:
  coordinación multi-IA" is demonstrated with exactly one tool today; the
  "symlink another entry file to AGENTS.md" pattern is only described in
  prose. Cheap, but arguably unnecessary if "one example + documented
  pattern" is considered sufficient — worth asking before building.
